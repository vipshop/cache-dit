cache-dit wheel index

PEP 503 index of the Cache-DiT wheels with the SVDQuant CUDA extension compiled in. The extension is built for the CUDA 13 toolkit, so pick the CUDA your torch was built against (python -c "import torch; print(torch.version.cuda)"): 

pip install cache-dit --extra-index-url https://vipshop.github.io/cache-dit/whl/cu13/

Install torch first. These wheels link against a CUDA 13 torch; nothing here carries torch of its own, so pip only resolves it when it is missing -- from PyPI, where it is not the cu13 build. Install it from the PyTorch index you normally use, then install this package.

The command adds this index as --extra-index-url rather than --index-url: it holds cache-dit alone, with no dependencies, so PyPI has to stay the index those come from. That is also the form uv resolves: it searches the extra indexes before the default one, so naming PyPI as the extra index instead would leave it considering the PyPI release only.

cache-dit is the same distribution PyPI lists, built here with the SVDQuant extension compiled in and tagged with the local version +cu13. That suffix is what keeps the two apart: on the same version it sorts above the plain release, so pip takes this build, and a pure-Python wheel of that version which is already installed no longer satisfies the requirement unchanged. Installing this replaces it -- one distribution, one cache_dit/ package. It also supersedes the retired cache-dit-cu13 distribution.

Pin the version when the channel is what you want: cache-dit==<version>+cu13. An unpinned pip install -U cache-dit takes the highest version across the indexes, so a newer pure-Python release on PyPI would win over an older build here, and the install would quietly fall back to a wheel without the extension.

Platform tags: manylinux_2_38_x86_64 -- the tag reflects the GLIBC symbols the extension actually needs, so pip refuses a wheel this machine cannot run.
